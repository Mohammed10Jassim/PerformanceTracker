# 02 — Setup & Configuration

## 1. Prerequisites

| Requirement | Version used | Notes |
|-------------|--------------|-------|
| JDK | 21 | `pom.xml` sets `<release>21</release>` |
| Maven | 3.9+ | or use the bundled wrapper `./mvnw` / `mvnw.cmd` |
| PostgreSQL | 14+ (local: 18) | database `performance_tracker` |
| Keycloak | 26.x | runs separately, realm `rkt` |
| IntelliJ IDEA | optional | an `Application` run configuration already exists |

### 1.1 Ports

| Service | URL |
|---------|-----|
| Application | `http://localhost:8080` |
| Keycloak console | `http://localhost:8081` |
| Realm `rkt` issuer | `http://localhost:8081/realms/rkt` |

The application listens on **8080** (`server.port` in `application.properties`). If that port is
occupied by another local application, override it with `--server.port=<port>`.

## 2. Database setup

### 2.1 Create the database

```sql
CREATE DATABASE performance_tracker;
```

The app connects with `postgres` / `root` in the `dev` profile (see `application-dev.properties`).

### 2.2 Schema creation

In `dev` the schema is created automatically:

```properties
spring.jpa.hibernate.ddl-auto=update
```

Hibernate will create all tables, sequences, unique constraints and indexes on first start.

### 2.3 The one object Hibernate cannot create

`DepartmentRepository` generates department codes with a **native** query against a database
sequence that Hibernate does not create automatically:

```sql
CREATE SEQUENCE IF NOT EXISTS department_code_seq START WITH 100000001 INCREMENT BY 1;
```

| Object | Owner | Created by |
|--------|-------|-----------|
| `department_code_seq` | database owner | **manual** — run the `CREATE SEQUENCE` above once |
| `<table>_id_seq` (13 of them) | database owner | Hibernate, folded into the `GENERATED BY DEFAULT AS IDENTITY` column definitions |

Hibernate cannot create this sequence, so it must be created by hand before creating the first
department; otherwise `POST /departments/create` fails with a SQL error surfaced as HTTP 500.

## 3. Keycloak setup

### 3.1 Keycloak instance

Keycloak runs as a **separate, already-configured service** — it is not started by this project and
nothing in this repository manages it. The application only consumes it over HTTP.

| Setting | Value |
|---------|-------|
| Console | `http://localhost:8081` |
| Realm | `rkt` |
| Storage | Keycloak's own database, outside `performance_tracker` |

Keycloak's own tables are **not** in the `performance_tracker` database, which belongs to this
application alone.

### 3.2 Create the realm

Admin console → **Create realm** → realm id `rkt` → enable.

### 3.3 Create the clients

Three clients are used. Only the first two matter to the backend.

#### `performance-tracker` — the API client (public)

| Setting | Value | Why |
|---------|-------|-----|
| Client type | Public | the SPA obtains tokens with it |
| Direct access grants | Enabled | allows password grant for local testing |
| Client roles | `ADMIN`, `HR_ADMIN`, `MANAGER`, `EMPLOYEE` | these appear in the JWT |

The `performance-tracker` **client id is hardcoded** in
`KeycloakJwtRoleConverter.CLIENT_ID` — it is the key under which roles are read from
`resource_access`. Rename it and every authenticated request loses all its authorities.

#### `performance-tracker-admin` — the service account (confidential)

| Setting | Value |
|---------|-------|
| Client type | Confidential |
| Service accounts | Enabled |
| Client credentials | Enabled |
| Standard flow | Disabled (not needed) |
| Realm-management roles on the service account | `manage-users`, `query-users` |

The app authenticates against this client with `grant_type=client_credentials` to read and create
users through the Admin REST API. Without `manage-users` / `query-users`, every
`/keycloak/**` endpoint fails with 403.

The client secret is **not** in any properties file. It is read from the `KEYCLOAK_ADMIN_CLIENT_SECRET`
environment variable and must be supplied at runtime (see §5).

#### `performance-tracker-frontend` — SPA client

Public client used by the browser application for the authorization-code + PKCE flow. Not referenced
by backend configuration.

### 3.4 Assign roles to users

```bash
# get an admin token
TOKEN=$(curl -s -X POST \
  "http://localhost:8081/realms/master/protocol/openid-connect/token" \
  -d client_id=admin-cli -d username=admin -d password=admin -d grant_type=password \
  | jq -r .access_token)

# read the client-role ids
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8081/admin/realms/rkt/clients?clientId=performance-tracker" | jq '.[0].id'
```

Then assign a role:

```bash
curl -X POST \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '[{"id":"<ROLE_ID>","name":"EMPLOYEE"}]' \
  "http://localhost:8081/admin/realms/rkt/users/<USER_ID>/role-mappings/clients/<PERFORMANCE_TRACKER_CLIENT_ID>"
```

Only **7 of 151** users in the `rkt` realm currently carry `performance-tracker` roles; everyone else
authenticates but receives no `ROLE_*` authorities and can only reach the permit-list endpoints.

### 3.5 Two ways to get a token for testing

```bash
# 1. password grant (requires Direct Access Grants on performance-tracker)
curl -s -X POST "http://localhost:8081/realms/rkt/protocol/openid-connect/token" \
  -d client_id=performance-tracker \
  -d username=mohammed.jassim@kirtitec.com \
  -d password='<password>' \
  -d grant_type=password | jq -r .access_token

# 2. Resource Owner Password (same as above) / authorization code via the SPA
```

Inspect the token to confirm your roles are present:

```bash
echo "$TOKEN" | cut -d. -f2 | base64 -d 2>/dev/null | jq '.resource_access["performance-tracker"]'
```

If `resource_access` is missing the client roles, the JWT → authority conversion yields no roles.

## 4. Configuration files

### `application.properties` (always loaded)

```properties
spring.application.name=PerformanceTracker
spring.profiles.active=dev
server.port=8080
spring.jpa.open-in-view=false
spring.jpa.show-sql=false
spring.jpa.properties.hibernate.format_sql=false
logging.level.root=INFO
logging.level.com.pt.PerformanceTracker=INFO
management.endpoints.web.exposure.include=health,info
app.cors.allowed-origins=${CORS_ALLOWED_ORIGINS:...}
```

| Property | Effect |
|----------|--------|
| `spring.profiles.active=dev` | `dev` is the default profile, so a plain IntelliJ run picks it up |
| `server.port=8080` | the port the application listens on |
| `spring.jpa.open-in-view=false` | lazy relations must be initialised inside service transactions |
| `management.endpoints.web.exposure.include=health,info` | only health and info are exposed (both public) |

### `application-dev.properties`

```properties
# Database
spring.datasource.url=jdbc:postgresql://localhost:5432/performance_tracker
spring.datasource.username=postgres
spring.datasource.password=root
spring.datasource.driver-class-name=org.postgresql.Driver

# JPA
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=false

# Keycloak Resource Server
spring.security.oauth2.resourceserver.jwt.issuer-uri=http://192.168.0.120:8081/realms/rkt
spring.security.oauth2.resourceserver.jwt.jwk-set-uri=http://192.168.0.120:8081/realms/rkt/protocol/openid-connect/certs

# Keycloak Admin API
keycloak.admin.server-url=http://192.168.0.120:8081
keycloak.admin.realm=rkt
keycloak.admin.target-realm=rkt
keycloak.admin.client-id=performance-tracker-admin
keycloak.admin.client-secret=${KEYCLOAK_ADMIN_CLIENT_SECRET}

# One-time user import
keycloak.admin.import-file=classpath:users.json
keycloak.admin.initial-password=password

# Logging
logging.level.root=INFO
logging.level.com.pt.PerformanceTracker=DEBUG
logging.level.org.springframework.security=TRACE
logging.level.org.hibernate.SQL=DEBUG
logging.level.org.hibernate.orm.jdbc.bind=TRACE

# swagger
springdoc.api-docs.path=/v3/api-docs
springdoc.swagger-ui.path=/swagger-ui.html
springdoc.swagger-ui.operations-sorter=method
springdoc.swagger-ui.tags-sorter=alpha
```

> The dev config points at `192.168.0.120:8081`. That is the machine's own Wi-Fi address, so it
> works locally — but it breaks on any other host or when the IP changes. Replace with
> `http://localhost:8081` for a laptop-only setup.

### `application-prod.properties`

Fully environment-driven, nothing hardcoded:

| Variable | Purpose |
|----------|---------|
| `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | datasource |
| `KEYCLOAK_ISSUER_URI`, `KEYCLOAK_JWK_SET_URI` | JWT validation |
| `KEYCLOAK_SERVER_URL` | admin API base URL |
| `KEYCLOAK_ADMIN_REALM` | realm the service account authenticates in |
| `KEYCLOAK_TARGET_REALM` | realm whose users are read/created |
| `KEYCLOAK_ADMIN_CLIENT_ID`, `KEYCLOAK_ADMIN_CLIENT_SECRET` | service account credentials |
| — | `ddl-auto=validate`, SQL logging off |

`KEYCLOAK_ISSUER_URI` is the **public** URL (`http://localhost:8081/realms/rkt`) because it must match
the `iss` claim Keycloak mints, and `KEYCLOAK_JWK_SET_URI` must point at the same instance's certs
endpoint.

`keycloak.admin.import-file` and `keycloak.admin.initial-password` are **absent** in prod, so
`POST /keycloak/import-users` cannot work under the prod profile (it fails with an unresolved
`IllegalStateException`).

## 5. Environment variables

The `dev` profile reads exactly one variable from the environment:

| Variable | Required | Used by |
|----------|----------|---------|
| `KEYCLOAK_ADMIN_CLIENT_SECRET` | **yes** | `keycloak.admin.client-secret` |

Because it is referenced as `${KEYCLOAK_ADMIN_CLIENT_SECRET}` with no default, **the application will
not start without it**. Supply it in one of these ways:

```bash
# bash / Git Bash
export KEYCLOAK_ADMIN_CLIENT_SECRET='<secret>'
./mvnw spring-boot:run
```

```powershell
# PowerShell (current session)
$env:KEYCLOAK_ADMIN_CLIENT_SECRET='<secret>'
.\mvnw.cmd spring-boot:run
```

```powershell
# PowerShell (persistent, user scope)
[Environment]::SetEnvironmentVariable('KEYCLOAK_ADMIN_CLIENT_SECRET','<secret>','User')
```

```bash
# Maven / Spring Boot plugin
mvn spring-boot:run "-Dspring-boot.run.arguments=--keycloak.admin.client-secret=<secret>"
```

In IntelliJ: **Run → Edit Configurations → PerformanceTracker → Environment variables**.

Do **not** commit the secret. It currently lives in `.idea/workspace.xml`, which is normally
git-ignored — verify with `git check-ignore .idea/workspace.xml`.

## 7. Local environment verification checklist

```bash
# 1. PostgreSQL reachable
pg_isready -h localhost -p 5432

# 2. database exists
psql -h localhost -U postgres -lqt | grep performance_tracker

# 3. the sequence Hibernate cannot create
psql -h localhost -U postgres -d performance_tracker -c '\ds department_code_seq'

# 4. realm is live
curl -s -o /dev/null -w '%{http_code}\n' \
  http://localhost:8081/realms/rkt/.well-known/openid-configuration   # expect 200

# 5. service account can authenticate (client_credentials)
curl -s -X POST http://localhost:8081/realms/rkt/protocol/openid-connect/token \
  -d grant_type=client_credentials \
  -d client_id=performance-tracker-admin \
  -d client_secret="$KEYCLOAK_ADMIN_CLIENT_SECRET" | jq -r .token_type   # expect "Bearer"

# 6. app up and secured
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/actuator/health   # 200
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/departments       # 401
curl -s http://localhost:8080/departments -H "Authorization: Bearer $TOKEN"      # 200

# 7. role authorization (needs a token whose performance-tracker client role is EMPLOYEE)
curl -s -o /dev/null -w '%{http_code}\n' \
  http://localhost:8080/users -H "Authorization: Bearer $EMPLOYEE_TOKEN"          # 403
```

Step 3 returning no rows means `department_code_seq` is missing. Step 4 returning 404 means the realm
does not exist. Step 5 returning 401 means the client id or secret is wrong. Step 6 returning 401 on
`/departments` is the expected unauthenticated response. Step 7 must return 403 — a 500 there means
an authorization denial is being reported with the wrong status code.

> Users in the `rkt` realm have no preset password, so the password grant only works after a password
> has been set for that user, e.g. via the Keycloak console or
> `POST /admin/realms/rkt/users/{id}/reset-password`. Set your own throwaway value; do not commit it.

## 8. Postman workspace

| Path | Purpose |
|------|---------|
| `postman/globals/workspace.globals.yaml` | workspace-level variables |

If you use the Postman collection, store the access token in the environment rather than in the
